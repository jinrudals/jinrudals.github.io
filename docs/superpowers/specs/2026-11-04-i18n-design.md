# i18n Design

## Goal
Serve the site in Korean (default) and English, including UI strings, fixed pages, and Markdown posts. First-time visitors with an English browser are redirected to English; the choice is persistable.

## Decisions
- Languages: `ko` (default, served at `/`), `en` (served at `/en/...`).
- Hand-rolled i18n; no new dependencies (static prerender, small site).
- Auto-detection is client-side only (GitHub Pages is static).

## Routing
- Move all routes under `src/routes/[[lang=lang]]/`. Param matcher `src/params/lang.ts` accepts only `en`.
- Root `+layout.ts` resolves `lang = params.lang ?? 'ko'` and returns it as `data.lang`.
- Prerender both variants via `entries` returning `[{ lang: undefined }, { lang: 'en' }]` combined with existing slug entries.

## UI strings
- `src/lib/i18n.ts`: `type Lang = 'ko' | 'en'`, `dict` with `ko`/`en`, `t(lang, key)`, `localePath(lang, path)`, `switchPath(pathname, to)`.
- Nav labels, footer, list headings, theme-button label, read-time text, and empty states move into the dict.

## Fixed pages and data
- `career.ts` fields become `{ ko, en }` localized values; pages pick by `lang`.
- about / resume / career page copy comes from the dict or localized data. English copy is a first draft to be polished by the author.

## Markdown content
- Files: `slug.md` (ko), `slug.en.md` (en) under `src/content/<section>/`.
- `content.ts` globs become language-aware: `listEntries(section, lang)` returns entries of that language; `getEntry(section, slug, lang)` returns the language version, falling back to ko.
- English list shows only posts with an English version. Direct access to an untranslated slug under `/en/` renders the Korean original with a "Korean original" notice.
- Prerender `entries` for `[slug]` routes include the en slugs plus ko slugs reachable via fallback.

## Detection and switching
- Inline script in `app.html`: if `localStorage.lang` is unset, `navigator.language` starts with `en`, and path is not under `/en/`, `location.replace('/en' + path)` and store `lang=en`. If set, honor it the same way (ko stored on `/en/` paths redirects to ko).
- Header `KO | EN` toggle links to the counterpart path via `switchPath` and stores the choice on click.
- `<html lang>` is updated by the layout; `<link rel="alternate" hreflang>` for ko/en/x-default is emitted per page via `<svelte:head>`.

## Error handling
- Unknown dict key: fall back to ko, then to the key itself.
- Missing translated post: ko fallback as above.

## Verification
- `npm run check` and `npm run build` pass.
- Built output contains `build/en/<route>/index.html` for every route, with `lang="en"` set and a correct toggle link.
- Playwright smoke check against `npm run preview`: English browser locale redirects `/` to `/en/` once; toggle persists across reloads.
- `localePath`/`switchPath` are pure functions.

## Out of scope
- More than two languages, translated slugs, per-language RSS, automatic machine translation.
